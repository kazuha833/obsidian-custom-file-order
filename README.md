# 自定义文件排序（Custom File Order）

一个 Obsidian 插件：让文件浏览器里的**文件与文件夹按你拖出来的顺序排列**，顺序按文件夹分别保存。

Obsidian 原生只提供「按名称 / 修改时间 / 创建时间」排序，同一目录下文件和文件夹永远固定分组。
本插件补上「手动顺序」这一项能力，并且**只影响显示顺序**，不移动、不重命名、不改动任何文件。

## 功能

- **拖拽排序**：文件 / 文件夹行最左侧出现 `⠿` 手柄，按住上下拖动即可调整顺序，松手立即保存。
- **右键菜单**：右键任意文件或文件夹 →「自定义排序」→ 上移 / 下移 / 置顶 / 置底 / 重置本文件夹顺序。
- **命令面板**：`自定义排序：上移当前文件`、`下移`、`置顶`、`置底`、`重置当前文件夹的顺序`，可自行绑定快捷键。
- **按文件夹独立记忆**：每个文件夹保存自己的顺序，互不干扰；根目录也有独立顺序。
- **对新增内容友好**：新创建的文件 / 文件夹若不在已保存的列表里，自动排到末尾并保持原生排序。
- **跟随重命名**：重命名文件会同步更新记录；重命名 / 移动文件夹会把整棵子树的顺序一起迁移；删除文件会清理记录。
- **总开关**：设置里可一键关闭，立即恢复 Obsidian 原生排序（已保存的顺序不会丢失）。

## 安装

把 `custom-file-order` 整个文件夹放进：

```
<你的库>/.obsidian/plugins/custom-file-order/
```

即目录内至少有 `main.js`、`manifest.json`、`styles.css` 三个文件。

然后打开 Obsidian → 设置 → 第三方插件 → 已安装插件，点击刷新后启用「自定义文件排序」。

也可以装 [BRAT](https://github.com/TfTHacker/obsidian42-brat)，添加仓库 `kazuha833/obsidian-custom-file-order`，
之后插件更新会自动同步。

## 使用

1. 打开左侧文件浏览器。
2. 把鼠标移到某个文件或文件夹行左侧，出现 `⠿` 手柄。
3. 按住手柄上下拖动：拖动中的行会变淡，目标位置会出现一条蓝色插入线，松手即保存。
4. 不方便拖拽时（例如触控板、或想一次移动很远），用右键菜单或命令面板。

> 拖拽结果只看**松手时指针落点**，不依赖 DOM 是否被重绘：
> 文件浏览器在子文件夹里会频繁重绘（虚拟滚动、折叠展开），因此这一点对深层目录尤其重要。

## 数据存放

顺序保存在插件目录下的 `data.json`：

```json
{
  "version": 1,
  "orders": {
    "/": ["00 首页.md", "参考", "算法"],
    "算法": ["排序算法.md", "动态规划.md"]
  },
  "settings": { "enabled": true, "showGrip": true }
}
```

- 键是文件夹路径，根目录为 `/`；值是该文件夹下子项的名称数组。
- 想手动调整也可以直接编辑该文件，保存后在 Obsidian 里重载插件生效。

## 实现说明

- 核心是接住文件浏览器的 `getSortedFolderItems(folder)`：Obsidian 渲染任意文件夹的子项时都会走它，
  插件把返回值按用户顺序重排后再交回去，因此折叠、搜索、无限滚动、原生拖拽移动文件都不受影响。
- 拖拽手柄用 Pointer Events 实现：按住手柄的监听挂在 `document` 的**捕获阶段**（`closest('.cfo-grip')` 命中才启动），
  因此不依赖手柄自身能否收到事件，指针离开手柄、移出视图也不会丢事件；
  同时临时把该行 `draggable` 置为 `false` 并在捕获阶段拦掉 `dragstart`，避免被 Obsidian 的「拖动文件到文件夹」接管。
  拖动过程中不移动任何 DOM，只在目标位置画一条插入线。
- **坑位记录 1**：Obsidian 1.x 把 `data-path` 设在 `.nav-file-title` / `.nav-folder-title` 上，外层的 `.nav-file` / `.nav-folder` 并没有；
  读取行路径时必须往下找一层，否则同文件夹的行全被过滤掉，表现为「手柄能按、但拖不动」。
- **坑位记录 2**：库根目录的子项并不放在 `.nav-folder-children` 里，而是放在一个**没有 class 的 div** 中
  （只有子文件夹的子项才在 `.nav-folder-children` 里）。所以「兄弟行」不能用 `closest('.nav-folder-children')` 去找，
  那样的结果是回落到被拖行自身、一个兄弟都找不到 —— 表现为「子文件夹里能拖、根目录下拖不动」。
  现在的做法是：找到包含被拖行的那个文件浏览器视图，在其中按「父路径相同」筛选所有已渲染行，再按屏幕纵坐标排序，
  完全与 DOM 嵌套层级无关。
- 松手时**只按指针落点**计算新位置（以已保存的顺序为基准），再把该行直接挪到 DOM 里对应的位置。
  这一步不能省：Obsidian 的 `requestSort()` 只重排根一层，展开的子文件夹不会重新查询顺序，
  只有自己去挪 DOM，子文件夹里改完才不会「弹回原位」。
- 兼容性：依赖的是文件浏览器里长期存在的 `getSortedFolderItems` / `requestSort` 方法，
  若将来 Obsidian 改动内部实现，插件会自动退回原生排序并在控制台给出提示，不会影响正常使用。

## 已知限制

- 仅排序「文件浏览器」中的显示顺序；快速切换器、搜索、关系图谱等不受影响。
- 文件浏览器若被其他插件替换成完全不同的实现（极少见），拖拽手柄可能不出现，但不会报错。

## 排查

遇到「拖不动」时按顺序检查：

1. **插件是否加载**：设置 → 第三方插件 → 已安装插件，列表里能看到「自定义文件排序」且开关为开。
   若刚安装，需要重启 Obsidian（或在该页面点刷新后启用）。
2. **手柄是否出现**：文件浏览器里每行左侧应有一个很淡的 `⠿`，鼠标移上去变深。
   没有手柄说明插件没接管到视图，用下面的诊断命令确认。
3. **诊断命令**：命令面板执行「自定义排序：诊断」，会弹出统计（视图数 / 已接管数 / 手柄数），
   详细信息打印在开发者控制台（`Ctrl+Shift+I` → Console，搜索 `custom-file-order`）。
4. **诊断日志**：设置里打开「写入诊断日志」后，拖拽过程会写进库根目录的 `.cfo-debug.json`
   （含每行几何位置、`elementFromPoint` 命中链、每次拖拽事件）。默认关闭，平时不会往库里写任何文件。
5. 仍不行时，右键菜单的「上移 / 下移」若是有效的，说明排序数据层正常，问题只在拖拽交互；
   把控制台里以 `[custom-file-order]` 开头的日志发出来即可定位。
